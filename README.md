# private-RSI

**Learning to Improve from Private Experience: Differentially Private Recursive Agent Evolution (DP-RAE)**

This is a research plan for extending [DP-ES](https://github.com/StephCpa/dp-es)
(EMNLP 2026) from differentially private prompt optimisation to *meta-level
self-improvement* of LLM agents. A shared improver learns, under a fixed
user-level DP budget, from many tenants' private experience, and improves the
procedure that improves it.

> Status (2026-10-03): **WP0/WP1 calibration.** In addition to the plan and
> analysis documents, the repository contains MT-Ops v0, a minimal fixed-plan
> kernel and small non-DP Qwen2.5-7B pilots. The pilots show no private-minus-
> public gain. The headroom audit shows the v0 pilot contract could not show
> one by construction (see `docs/05_review_of_wp0_progress.md`). MT-Ops v1 now
> passes the scripted validity checks, and a three-seed Qwen usability check
> shows a 23.61 pp gain from supplying the true rule table. This is not a
> private-transfer or DP result; there are no DP-RAE results yet.

## Key findings so far (analytical, no LLM calls)

1. **DP-ES's private signal is nearly uninformative at the published setting.**
   The released score has noise std 1.0 on a [0, 1] accuracy. Picking the
   best of 18 such scores captures about 3 % of the oracle gain among good
   prompts (random choice: 0 %). The first experiment is therefore an ε = 0
   control (E0, about one GPU-day).
2. **At the same budget, full-batch scoring has 9.2× less noise** (std 0.109 vs
   1.0, ε = 0.705, δ = 10⁻⁵, 18 releases) at 20× the evaluation calls.
3. **The RSI loop's shape decides the mechanism.** Release-all noise grows like
   √(#tests). Sparse-vector acceptance tests pay per *accepted* upgrade and
   private selection per *generation*. The advantage depends on how many users
   each test can afford to evaluate, so the choice is a privacy, noise and
   compute trade-off.
4. **Data scale is binding.** Detecting a 5 pp meta-gain at ε = 1 needs about
   1,000–3,000 users. The no-DP floor is about 220.

## Reproduce the calibration

```bash
python -m pip install -r requirements.txt
python analysis/calibration.py            # writes results/calibration_output.md
python -m unittest discover -s tests -v   # accountant and mechanism checks
```

The accountant is self-contained (numpy + scipy). It matches dp-es's AutoDP
full-batch reference to 3 decimals and is checked against numerical
integration.
